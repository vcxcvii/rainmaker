# data.example

Fabricated data for a fictional company, `quillet.com`, a mid-market contract
review tool. Every number here is invented; the shapes match exactly what
`rainmaker audit`, `rainmaker serp`, and the strategy skills actually produce.

This exists so every skill can be developed and read against realistic data
with zero credentials and zero live site. Copy any file into `data/` (or
`context/`, for a real `business.md`) to try a skill without running a real
audit first.

- `strategy.json`, `competitors.json`, `citation-graph.json`, `blueprint.json` — the strategy layer
- `ledger.jsonl`, `state.json` — `state.json` is generated by replaying `ledger.jsonl` through the real `materialise()`, so it is guaranteed consistent with the ledger rather than hand-written
- `snapshots/2026-06-15T09-00-00Z/` — one full snapshot: `crawl.json`, `gsc.json`, `ga4.json`, `diagnosis.json`, `serp.json`, `citations.json`

Two things are deliberately illustrated in this fixture set:

1. `/pricing` is a declared primary conversion in the example config with `ga4.json` showing zero `key_events` on it, while `/demo` (also declared) shows 41. This is exactly the "declared conversion page with no measured key events" case `follow-the-money` is built to surface first.
2. The ledger shows `t0:noindex:/demo` sitting in `in_progress` with no `shipped` event, and `crawl.json` still shows that page noindexed. `diagnosis.json` correctly still lists it as an open finding. Nothing here fakes a fix that the underlying data doesn't back up.
